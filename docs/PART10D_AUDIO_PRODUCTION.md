# Phase 10D recording production

## Implementation

Audio recordings are bundled as local assets.

The application does not require a streaming service
or remote audio URL for these practices.

The player requires an explicit play action.

Playback pauses on backgrounding, route changes
and privacy cover activation.

The user can choose the timed text alternative.

## Recording workflow

1. Export the current recording cue sheets.
2. Review the scripts and intended quiet intervals.
3. Produce the approved recordings.
4. Verify the spoken transcript and cue timings.
5. Verify voice, recording and distribution rights.
6. Measure the actual finished duration.
7. Place the MP3 in assets/audio.
8. Generate its review record.
9. Complete the review record truthfully.
10. Synchronise the bundled asset registry.
11. Run all source checks.
12. Test on physical devices.

## Review limitations

The toolkit verifies approval fields, transcript
fingerprints and audio file fingerprints.

It does not establish that a reviewer is qualified,
that rights were genuinely obtained, or that a
recording is clinically appropriate.

Duration is entered after actual manual measurement.
The toolkit does not decode or analyse MP3 audio.

Production scripts and recordings require human review.

## Device checks

- Bundled playback without internet.
- Pause and resume.
- Replay and seeking.
- Accurate text cue timing.
- Text alternative availability.
- Audio interruption and headphone disconnection.
- Background and biometric lock behaviour.
- No unexpected playback on opening a practice.
- No sensitive playback metadata on the lockscreen.
- Free access to both essential recordings.
